# 녹음·자막 맞추기

## 녹음 방식별 정확도 (가짜 녹음 49장면으로 시험한 결과)

| 방식 | 조건 | 결과 |
| --- | --- | --- |
| 장면별 파일 | — | 항상 정확(파일 = 장면) |
| 한 파일 + `--srt` | 장면 사이 쉼이 짧고(0.8~1.5초) 읽는 속도 ±40%, 자막 글자 13% 틀림 | 49/49 |
| 한 파일, 쉼만 | 장면 사이 1.2~2.2초, 장면 안 숨 0.3~0.8초, 속도 ±30% | 49/49 |
| 한 파일, 쉼만 | 장면 사이 쉼이 장면 안 숨과 비슷(0.8~1.5초 vs 0.3~1.0초) | 34/49 → `--start`로 고침 |

그래서 사용자에게는 이렇게 부탁한다: "장면이 바뀔 때 2초쯤 확실히 쉬어 주세요. 녹음 프로그램(Vrew, CapCut 등)이 자막 파일(SRT)을 만들어 주면 같이 주세요."

## align-voice.py

```bash
python3 scripts/align-voice.py 녹음.m4a                       # 쉼 + 대본 길이
python3 scripts/align-voice.py 녹음.m4a --srt 자막.srt        # 자막 글자로(가장 정확)
python3 scripts/align-voice.py 녹음.m4a --start s12=3:41      # 경계 고정(여러 번 써도 됨)
```

- 원본 소리를 쓰는 영상 장면(`clip` + `withSound: true`)은 녹음에 없다고 보고 건너뛴다.
- 결과: `public/voice/<id>.m4a`, `src/data/voice.ts`(자동으로 다시 씀), `--srt`면 `src/data/captions.ts`의 해당 장면 자막.
- 녹음 파일 대신 mp4를 줘도 소리만 꺼내 쓴다.
- 표의 `예상대비`(쉼 방식): 실제 길이 ÷ 대본으로 예상한 길이. 0.55 미만·1.8 초과면 ⚠. `겹침`(SRT 방식): 대본과 자막 글자 겹침(0~1). 0.45 미만이면 ⚠.
- ⚠가 붙거나 사용자가 "여기 어긋났어요"라고 하면: 그 장면이 실제로 시작하는 시각을 받아 `--start id=분:초`로 다시 실행한다. 경계 하나가 틀리면 보통 앞뒤 두 장면만 틀리므로, 틀린 쌍의 **뒤 장면** 시작을 고정한다.
- 같은 장면을 두 번 읽은 녹음(다시 읽기)은 개수가 어긋난다. 그 부분은 잘라 내거나 해당 장면만 따로 녹음해 달라고 한다.

동작 원리(고칠 때 참고): 쉼 방식은 ffmpeg `silencedetect`(-35dB, 0.45초 이상)로 쉼 후보를 찾고, 장면 n개에 경계 n-1개를 동적 계획법으로 고른다. 비용 = Σ(log(실제/예상 길이))² − 2.5 × (쉼 길이/가장 긴 쉼). SRT 방식은 자막 줄들을 순서대로 묶되 각 묶음과 장면 대본의 글자 두 개씩 묶음(bigram) 겹침(Dice)이 최대가 되게 하고, 글자 수 차이에 작은 벌점(0.3 × log비²)을 준다.

## 자막 보이기

- 렌더할 때 자막을 켜면(`npm run render:subtitles`) 장면마다 `captions.ts`의 실제 자막 시각을 쓰고, 없으면 대본 줄을 글자 수 비율로 나눠 보여 준다.
- 말하며 녹화한 영상: 장면을 `clip`으로 만들고(`from`/`to`는 자막 시각을 보고 주제별로 끊는다), `withSound: true`, 그다음 `python3 scripts/captions-from-srt.py 자막.srt [영상파일]`.
- 유튜브에 자막을 따로 올릴 거라면 자막을 영상에 넣지 않고 SRT만 전달하는 편이 낫다. 사용자에게 어느 쪽인지 묻는다.

## 녹음 후 마무리

1. `npm run script` → 대본.md 타임스탬프가 실제 녹음 길이로 바뀐다(유튜브 설명란용).
2. `npm run stills` 몇 장으로 확대 시점이 말과 맞는지 본다(확대는 장면 22~42% 지점).
3. `npm run render` → 영상 끝부분과 장면 경계 몇 곳의 프레임을 뽑아 확인한 뒤 전달.
