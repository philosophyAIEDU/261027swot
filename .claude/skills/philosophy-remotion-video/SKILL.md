# 필로소피 파스텔 Remotion 영상

캡처·화면 녹화·녹음·자막을 받아, 필로소피 AI 교육 채널 느낌의 파스텔 톤 설명 영상(1920×1080, 30fps)을 만든다.
`assets/template/`은 실제로 9.6분짜리 영상을 만들면서 다듬은 Remotion 프로젝트이고, 모든 장면이 `src/data/scenes.ts` 데이터 하나로 움직인다. 새 영상은 이 템플릿을 복사해 데이터만 채우는 방식으로 만든다.
코드를 새로 짜기보다 데이터(scenes.ts)를 잘 쓰는 데 시간을 쓰는 것이 이 스킬의 요점이다.

## 영상의 모양

- 바탕: 천천히 떠다니는 파스텔 방울(라벤더·민트·복숭아·하늘·버터) + 점 무늬. 글자는 항상 진한 남보라(`#2B2645`)라 밝은 바탕에서도 또렷하다.
- 글꼴: 제목 Jua(둥글고 친근함), 본문 Noto Sans KR. 둘 다 파일로 넣어 두어 렌더 결과가 늘 같다.
- 장면 종류(`kind`): `title`(오프닝, 형광펜 제목) · `brief`(주제 소개 카드+타일) · `flow`(단계 흐름도) · `chapter`(STEP 표지) · `shot`(캡처를 앱 창 액자에 넣고 확대+스포트라이트) · `clip`(화면 녹화 영상, 같은 액자) · `photos`(사진 두 장 폴라로이드) · `cards`(정리·당부 카드) · `outro`(좋아요·구독).
- 위쪽 줄: 시리즈 이름 + 단계 진행 표시. 캡처·영상 장면 오른쪽: STEP 배지, 단계 이름, 핵심 문구 카드(차례로 등장).
- 장면 전환: 기본 페이드, 단계 표지로 넘어갈 때 오른쪽에서 밀려 들어옴.

장면별 데이터 필드와 예시는 `references/scenes-reference.md`에 있다. scenes.ts를 쓰기 전에 읽는다.

## 작업 순서

### 1. 받은 자료 확인

무엇이 있는지 먼저 정리한다: PPT/캡처, 화면 녹화(mp4·mov), 자막(SRT), 대본·메모, 녹음(한 파일인지 장면별인지), 참고할 이전 영상.
없는 것은 지어내지 말고, 영상에 꼭 필요한 것만 짧게 묻는다. 예를 들어 이전 영상 내용을 볼 수 없다면 오프닝에서 그 내용을 단정하지 말고, 사용자에게 확인을 부탁한다.
녹음은 보통 "영상·대본을 먼저 만들고 → 사용자가 대본 보고 녹음 → 녹음을 받아 싱크" 순서다. 녹음이 이미 있으면 7단계로 바로 간다.

### 2. 프로젝트 만들기

```bash
bash <이 스킬 폴더>/scripts/new-project.sh <만들 폴더>     # 예: video-ep3
```

템플릿 복사 → 글꼴 받기 → 예시 그림·영상 만들기 → `npm install` → 크기 표 → 타입 검사까지 한 번에 한다(약 40초).
저장소 안에서 일한다면 앱 코드와 섞이지 않게 별도 폴더(예: `video/`, `video-ep3/`)에 만든다.

### 3. 자료 넣기

- PPT: `python3 scripts/extract-pptx.py 발표.pptx` → 슬라이드 순서대로 `public/shots/s01.png …`. 슬라이드 글자와 **발표자 노트**는 `slides.json`에 모인다(노트에 하고 싶은 말이 들어 있는 경우가 많으니 꼭 읽는다).
- 캡처는 `public/shots/`, 화면 녹화는 `public/clips/`에 둔다.
- 예시 파일(`sample.png`, `sample.mp4`)과 예시 장면은 실제 자료로 바꾼 뒤 지운다.
- 넣고 나면 `npm run media`(크기·길이 표 `src/data/media.ts`).

### 4. 자료를 모두 직접 본다

모든 캡처를 Read 도구로 하나씩 열어 본다. 화면 녹화는 몇 초 간격으로 프레임을 뽑아서 본다:
`ffmpeg -i public/clips/x.mp4 -vf fps=1/3 /tmp/frames_%03d.png`
이유: 이야기 순서, 확대할 위치(`focus`), 가려야 할 정보(`blur`: API 키·이메일·전화번호·얼굴·계정 ID)는 화면 내용을 봐야만 정할 수 있다. 보지 않고 쓴 focus는 엉뚱한 곳을 확대한다.

### 5. 이야기와 대본 쓰기

- 자료 순서를 따르되, 같은 주제끼리 묶는 게 더 자연스러우면 순서를 바꾸고 사용자에게 그렇게 했다고 알린다.
- 단계(`CHAPTERS`)는 3~5개가 보기 좋다. 단계 안의 작은 소제목은 `round`로 쓴다(예: "다시 요청 ① 개념 설명").
- 대본 말투는 필로소피 채널 말투로 쓴다. `philosophy-ai-youtube-script-generator` 스킬이 있으면 그 지침을 따르고, 없으면 `references/narration-guide.md`를 따른다. 핵심: "안녕하세요 필로소피입니다 :)"로 시작, 짧은 구어체 줄(숨 쉬는 곳마다 줄바꿈), 단계마다 "이걸 왜 하냐면" 설명, "오늘의 영상 여기까지입니다 … 좋아요와 구독 …"으로 끝.
- 분량은 5~10분 영상 기준 1,500~3,000자(공백 제외). 장면 길이는 대본 글자 수로 자동 계산된다(초당 약 5.5자).
- `points`(핵심 문구)는 장면당 1~3개, 한 줄 20자 안팎. 대본을 그대로 옮기지 말고 화면에서 한눈에 읽힐 요점만.
- 사실(숫자·날짜·다른 회사 이야기)은 자료에 있는 것만 쓴다.

### 6. 점검하고 렌더링

```bash
npx tsc --noEmit             # 타입 검사
npm run stills               # 장면마다 정지 화면 out/stills/<id>.png (특정 장면만: node scripts/stills.ts s03 s07)
```

정지 화면은 Read로 열어 하나하나 본다. 처음 렌더에는 거의 늘 고칠 것이 있다. 볼 것:
- 확대·스포트라이트가 의도한 곳에 있는가(focus 좌표는 그림 기준 0~1 비율 — 어긋나면 고치고 그 장면만 다시 `stills`).
- 가려야 할 정보가 blur로 완전히 덮였는가(확대 전 화면에서 확인: 장면 앞부분 프레임으로 `npx remotion still Main x.png --frame=N`).
- 글자가 넘치거나 낱말 중간에서 줄이 바뀌지 않는가(전체에 `word-break: keep-all`이 걸려 있지만 카드가 좁으면 문구를 줄인다).
- 핵심 문구 카드가 3개를 넘지 않는가, 제목이 두 줄 넘게 늘어지지 않는가.

그다음 `npm run script`로 `대본.md`를 만들어 사용자에게 보내고(SendUserFile이 있으면 그것으로), 렌더링은 백그라운드로 돌린다:

```bash
npm run render     # = bash scripts/render-chunks.sh out/video.mp4
```

1분(1800프레임)씩 나눠 만들고 이어 붙인다. 10분 영상은 이 환경(4코어)에서 30분 이상 걸릴 수 있고, 컨테이너가 다시 시작되면 렌더가 끊긴다. 다시 실행하면 끝난 조각은 건너뛰므로 그냥 다시 돌리면 된다. 소스·그림·녹음이 바뀌면 조각을 자동으로 새로 만든다.
완성 파일은 몇 장면을 다시 확인한 뒤 전달한다. mp4는 용량이 커서 git에 넣지 않는다(`out/`은 .gitignore).

### 7. 녹음·자막을 받으면

자세한 방법과 문제 해결은 `references/voice-and-subtitles.md`. 요약:

| 받은 것 | 할 일 |
| --- | --- |
| 장면별 녹음 파일 | `public/voice/`에 넣고 `src/data/voice.ts`에 `id: 'voice/파일'` 적기 |
| 한 번에 녹음한 파일 | `python3 scripts/align-voice.py 녹음.m4a` — 쉼과 대본 길이로 나눔 |
| 한 번에 녹음 + 자막(SRT) | `python3 scripts/align-voice.py 녹음.m4a --srt 자막.srt` — 자막 글자로 나눔(가장 정확), 자막도 장면에 들어감 |
| 말하며 녹화한 영상 + 자막 | 장면을 `clip`(`from`/`to`/`withSound: true`)으로 만들고 `python3 scripts/captions-from-srt.py 자막.srt` |

나눈 뒤 나오는 표(장면별 시작 시각, ⚠ 확인 필요)를 사용자에게 보여 준다. Claude는 소리를 들을 수 없으므로, 경계가 맞는지 몇 군데 들어 봐 달라고 부탁하고, 어긋난 경계는 `--start 장면id=분:초`로 고정한다.
그다음 `npm run script`(실제 녹음 길이로 타임스탬프가 바뀜) → `npm run stills` 몇 장 → `npm run render`(자막을 원하면 `npm run render:subtitles`).

## 이 환경에서 알아 둘 것

- 렌더용 크롬: `remotion.config.ts`가 `/opt/pw-browsers/...chrome-headless-shell`이 있으면 그것을 쓴다(없으면 Remotion이 받는다).
- 음성 인식 모델(Whisper 등)은 받을 수 없는 환경이 많다. 그래서 녹음 싱크는 쉼·대본 길이(기본) 또는 사용자가 준 SRT로 한다. SRT가 있으면 꼭 쓴다.
- 오래 걸리는 렌더는 `run_in_background`로 돌리고, 끝나면 알림을 받는다. `--log=error`라 진행 상황은 `out/chunks/` 조각 수로 확인한다.
- 프로세스를 끌 때 `pkill -f "vite preview"`처럼 쓰면 그 명령을 실행하는 셸 자신도 걸려 함께 꺼진다. `pkill -f "remotion rende[r]"`처럼 대괄호 하나를 넣는다.
- 렌더 결과물(mp4, 정지 화면)은 저장소에 넣지 않는다. 소스·캡처·글꼴만 커밋한다.
- Remotion은 개인과 직원 3명 이하 회사는 무료, 그보다 큰 회사·기관은 회사용 라이선스가 필요하다. 처음 만들어 줄 때 한 번 알려 준다.

## 사용자에게 전할 때

사용자는 개발자가 아닐 수 있다. 명령어 대신 "무엇을 했고, 무엇을 확인해 주면 되는지"를 쉬운 말로 전한다.
보낼 것: `대본.md`(녹음 방법 포함), 완성 영상, (녹음 싱크 후) 장면별 시작 시각 표, 확인이 필요한 부분(볼 수 없었던 자료, 추측으로 쓴 문장, 가린 정보).
